5분 시작하기

Docker Desktop과 Python 3가 설치되어 있으면 됩니다. MySQL 컨테이너가 처음 뜰 때 스키마, 트리거, 테스트 데이터가 자동으로 적재됩니다.

  1. 저장소 받기

    git clone https://github.com/moovingGun/database-teamproject.git && cd database-teamproject

    저장소: github.com/moovingGun/database-teamproject (비공개 저장소이므로 팀원의 GitHub 계정을 Collaborator로 추가해야 받을 수 있습니다)

  2. DB 기동 (최초 1회 자동 적재)

    docker compose up -d

  3. 웹 앱 실행

    python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python run.py

    브라우저에서 http://127.0.0.1:5001 접속 (5000은 macOS AirPlay가 쓰는 경우가 많아 5001을 사용)

  4. 데모 계정으로 로그인

    아이디역할볼 수 있는 것
    ceo, exec01경영진직원 검색, 투입 관리, 시점별 현황, 평가·인센티브 리포트
    pm01특급 개발자, 종료 프로젝트 PMPM 평가 입력, 고객 평가 의뢰와 보고
    dev01중급 개발자내 정보·기술 관리, 동료 평가

    비밀번호는 모두 pass1234. 데이터를 처음 상태로 되돌리려면 ./db/reset.sh

설계 핵심

과제의 핵심 가이드라인 5개를 어떻게 만족했는지입니다. 상세 근거는 docs/02_ERD.md와 docs/07_핵심설계결정.md에 있습니다.

가이드라인반영
직원 · 프로젝트 평가는 슈퍼타입-서브타입employee 아래 developer / staff, evaluation 아래 customer_eval / pm_eval / peer_eval. 서브타입 PK가 슈퍼타입 PK를 공유하고 판별자 불일치는 트리거가 거부
발주처는 별도 엔티티client와 client_contact로 분리. 고객 평가의 평가자가 담당자를 외래키로 참조
M:N 관계 지양개발자–기술, 프로젝트–기술, 개발자–프로젝트를 교차 엔티티 3개로 해소. ERD에 M:N이 없음
1:N에서 Total:Total 지양모든 1:N의 1측을 Partial로 설계. 예: 예정 프로젝트는 투입이 없고, 의뢰됨 상태의 고객 평가는 상세 점수가 없음
추가 비즈니스 로직 고도화투입률 합계 100%, PM 1명, 직무별 최소 등급, 자동 채번, 등급 변경 이력, 고객 평가 워크플로우, 가중치 기반 인센티브 등급

비즈니스 규칙

DB 트리거가 강제하는 규칙입니다. db/demo/constraint_tests.sql을 실행하면 아래 규칙이 실제로 거부되는 것을 한 번에 볼 수 있습니다.

번호규칙위치
BR-01개발자 서브타입만 프로젝트에 투입sp_validate_assignment
(투입 INSERT/UPDATE 트리거)
BR-03투입 기간은 프로젝트 기간 안
BR-04같은 프로젝트에 기간이 겹치는 중복 투입 금지
BR-05같은 기간 개인 투입률 합계 100% 이하 (순차 투입은 허용)
BR-06같은 기간 프로젝트 PM은 1명
BR-07직무별 최소 기술등급 충족 (PM 고급 이상 등)
BR-02사번 E+연도+일련번호, 프로젝트번호 P+연도-일련번호 자동 채번trg_employee_bi, trg_project_bi
BR-08 · 09평가는 종료 프로젝트만, 피평가자는 참여자만trg_evaluation_bi
BR-10 ~ 12서브타입과 판별자 일치, 고객 평가자는 발주처 담당자, 의뢰는 PM만trg_customer_eval_bi
BR-13 · 14PM 평가는 PM만·자기평가 불가·1건, 동료 평가는 참여자만·자기평가 불가·1건trg_pm_eval_bi, trg_peer_eval_bi
BR-15기술등급 변경 시 이력 자동 기록trg_developer_au

앱에서 강제하는 규칙: 종료·취소 프로젝트에 신규 투입 금지, 일반직원은 본인 정보만 조회·수정, 기술등급은 경영진만 변경, 고객 평가 보고는 의뢰한 PM만. 가중치(고객 40 · PM 40 · 동료 20)와 등급 기준(S 4.5 · A 4.0 · B 3.0)은 가정값이라 팀 합의로 조정하면 됩니다. 정책 테이블과 뷰에 모여 있어 코드 수정 없이 바꿀 수 있습니다.

발표 데모 흐름 (약 10분)

  1. 회원가입과 ID 중복확인

    dev01을 입력하고 중복확인을 누르면 거부 메시지, 새 아이디로 가입하면 사번 E26xxxx가 자동 부여됩니다.

  2. 경영진 조회

    ceo로 로그인해 대시보드(S1), 시점별 투입현황에서 2025-06-01 조회(S2), 직원 검색에서 기술과 가용일 필터(S6), 직원 상세(S3)를 보여줍니다.

  3. 투입 규칙 시연

    이미 100% 투입된 개발자를 다른 프로젝트에 넣으면 화면에 [BR-05] 투입률 합계 초과 메시지가 뜨고, 가용 개발자는 바로 등록됩니다.

  4. 평가 워크플로우

    pm01로 남은 팀원 PM 평가를 입력하고, 고객 평가 '의뢰됨' 링크를 열어 발주처 담당자 입장에서 제출한 뒤, PM이 회사에 보고 처리합니다.

  5. 결과 반영 확인

    경영진 평가 결과(S4)와 인센티브(S5) 리포트에서 방금 제출한 점수가 종합점수에 반영된 것을 확인합니다.

  6. DB 직접 시연

    constraint_tests.sql로 규칙 14종 거부를, demo_scenarios.sql로 S1~S6 결과를 터미널에서 보여줍니다.
